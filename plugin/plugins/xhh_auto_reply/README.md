# 小黑盒 AI 回帖

这个 N.E.K.O 插件参考 OpenXHH 的小黑盒社区请求方式，并复用 N.E.K.O 当前配置的 `conversation` 模型生成评论。

## 已支持

- 导入并私有保存小黑盒网页 Cookie。
- 读取帖子正文、评论楼层和图片相关 JSON 上下文。
- 在现有帖子下发布顶级评论。
- 回复指定评论（楼中楼）。
- 先生成 AI 草稿，确认后再发布。
- 轮询帖子/评论里的 @ 并自动生成回复。
- dry-run、用户 UID 白名单、请求限频、消息去重。

## 不支持

- 创建一个全新的社区主题帖。OpenXHH 没有提供可靠的主题帖创建接口实现，本插件不猜测未知接口。
- 黑盒语音频道或私信。它们属于 `heychat` 机器人体系，不是小黑盒社区评论接口。
- 自动上传本地图片。当前手动评论入口只接受已经可公网访问的小黑盒图片 URL。

## 使用

1. 在 N.E.K.O 中配置 conversation 模型。
2. 在浏览器登录小黑盒，打开开发者工具，从一个 `api.xiaoheihe.cn` 请求复制完整 `Cookie` 请求头。
3. 打开插件面板并导入 Cookie。
4. 保持 `dry-run=true`，点击“立即检查一次”为当前历史 @ 建立去重基线。
5. 使用“AI 生成帖子评论”验证帖子读取与模型生成，再按需关闭 dry-run、启动监听。

第一次检查默认只把接口当前返回的历史 @ 建立为去重基线，不会回复旧消息。只有调用 `run_poll_once(process_existing=true)` 才会处理已有历史消息。

Cookie、运行状态和去重记录保存在插件私有数据目录。不要把这些文件提交到 Git。

## 风险

该插件使用个人账号 Cookie 调用社区接口，不是官方机器人 Token。自动访问和自动评论可能触发验证码、HTTP 403 或账号风控。默认 dry-run 已开启，请使用保守的轮询和请求间隔。

## 实现来源说明

小黑盒请求签名、帖子读取、消息轮询和评论表单字段参考了用户提供的 OpenXHH 源码；AI 调用方式参考 N.E.K.O 内置 `qq_auto_reply`，使用 `create_chat_llm_async`、conversation 模型配置与 token 调用类型记录。所参考的 OpenXHH 工作区未发现许可证文件，后续公开分发前应由项目维护者确认许可与归属要求。
